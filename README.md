# TaskFlow MVP

[Посмотреть демо / Live Demo](https://task-tracker-nine-pi.vercel.app/)

Высокопроизводительный и отзывчивый Kanban-трекер задач, созданный для демонстрации современных подходов к разработке на React, архитектуры управления состоянием (state management) и паттернов оптимизации производительности.

---

## Технологический стек и архитектура

| Слой | Технология | Назначение |
| --- | --- | --- |
| **Фреймворк** | **React 18.3.1** | Компонентный UI со строгой оптимизацией рендеринга (memo, стабильные ссылки на колбэки) |

## Архитектурные решения и компромиссы

### 1. Разделение состояния (Паттерн трех слоев)
Для поддержания чистоты компонентов и предотвращения багов синхронизации состояние приложения строго разделено на три независимых слоя:
*   **Серверное состояние (TanStack Query):** Все данные проектов и задач, получаемые из API. Синхронизируются и кэшируются автоматически.
*   **Состояние URL (TanStack Router):** Поисковые запросы и фильтры сохраняются напрямую в URL (?q=search&priority=high). Это гарантирует, что состояние страницы полностью сохраняется при перезагрузке и им можно поделиться с другими пользователями.
*   **Состояние интерфейса (Zustand):** Временное клиентское состояние (например, открыта ли боковая панель деталей задачи или какая задача сейчас выбрана).

### 2. Имитация API в коде (In-Code Mock Client)
Вместо настройки тяжелого Mock Service Worker (MSW) или развертывания отдельного бэкенд-сервера, в проекте реализован **встроенный mock-клиент** (src/api/mockClient.ts).
*   **Как это работает:** Данные сохраняются в localStorage для персистентности, а методы возвращают нативные объекты Promise с искусственной задержкой (setTimeout(300)).
*   **Почему это эффективный компромисс:** Для TanStack Query нет никакой разницы между этим mock-клиентом и реальным сервером. Это позволяет приложению демонстрировать состояния загрузки, обработку ошибок и оптимистичные обновления без накладных расходов на инфраструктуру и со 100% надежностью при статическом деплое (например, на Vercel).

### 3. Нативный HTML5 Drag-and-Drop (Без внешних зависимостей)
Вместо подключения тяжелых сторонних библиотек для перетаскивания (таких как @dnd-kit или @hello-pangea/dnd), Kanban-доска построена на **нативном HTML5 Drag and Drop API**.
*   **Почему:** Демонстрирует глубокое понимание стандартов браузерных API.
*   **Производительность:** Решение абсолютно легковесно, не увеличивает размер бандла и обеспечивает максимальную скорость рендеринга.
*   **Оптимистичные обновления:** В связке с TanStack Query перетаскивание карточки в другую колонку мгновенно обновляет UI, а в случае гипотетической ошибки запроса состояние автоматически откатывается назад.

### 4. Конфигурация локализации (i18n)
Интернационализация настроена с помощью i18next и react-i18next. Файлы переводов находятся в директории src/locales/.
*   Выбранный язык сохраняется в localStorage и автоматически восстанавливается при повторном посещении.
*   Интерфейс полностью переведен на **русский** и **английский** языки.

## Структура проекта

```ini
src/
├── api/           # Слой работы с API (mockClient + хуки TanStack Query)
├── components/    # Переиспользуемые UI-компоненты (Button, Input, Badge и др.)
├── hooks/         # Кастомные React-хуки
├── i18n/          # Конфигурация i18next и хелперы локализации
├── locales/       # Файлы переводов (ru.json, en.json)
├── modules/       # Функциональные модули (доменные области: Board, TaskDetail)
│   ├── Board/     # Компоненты Kanban-доски, колонок и карточек задач
│   └── TaskDetail/# Боковая панель для просмотра и редактирования задачи
├── routes/        # Файловый роутинг TanStack Router
├── styles/        # Глобальные стили (index.css с директивами Tailwind)
├── types/         # Определение типов TypeScript
└── main.tsx       # Точка входа (инициализация i18n, QueryClient и Router)
```

## Запуск проекта

### Требования
*   Node.js (версии 18.x или выше)
*   npm (версии 9.x или выше)

### Установка и запуск
1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/your-username/task-tracker.git
   cd task-tracker
   ```

2. Установите зависимости:
   ```bash
   npm install
   ```

3. Запустите сервер разработки:
   ```bash
   npm run dev
   ```

4. Сборка для продакшена:
   ```bash
   npm run build
   ```

## Коммерческий опыт и NDA
Мой основной коммерческий опыт связан с разработкой крупных корпоративных SPA-приложений под NDA. В этих проектах активно используются **MUI 7, MUI X (DataGrid, DatePickers), генерация API по OpenAPI схемам и сложные микрофронтенд-архитектуры**.

Этот pet-проект спроектирован как лаконичная демонстрация моих **базовых навыков работы с React, TypeScript, Tailwind CSS и архитектурой управления состоянием** без избыточного веса корпоративных UI-китов.
